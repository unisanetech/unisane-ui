# Blocks catalog product contract gap

The docs application has a working block registry, catalog, detail pages, live previews,
and example code, but its future taxonomy, browse model, free/pro entitlement boundary,
and relationship to templates are not yet accepted product architecture.

The next product-focused Task must decide and prove:

- the component versus block versus full-template boundary
- stable groups and categories for application, commerce, marketing, and authentication
- metadata ownership, source/preview parity, search, filtering, and routing
- portability through public package or registry contracts rather than docs-app internals
- free/pro classification without locked-state advertising before an entitlement product
  exists
- accessibility, responsive preview, snippet correctness, and visual-regression gates

Current source remains authoritative. This Finding does not authorize the former
multi-phase implementation plan, a marketplace, user submissions, entitlements, or a
template product. Those require a separate Decision and Skopos Task after the repository
boundary is ready.
